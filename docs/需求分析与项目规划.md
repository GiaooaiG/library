# 📋 图书馆管理系统 - 需求分析与项目规划

## 一、项目背景

### 1.1 项目起源
随着信息技术的快速发展和数字化转型的深入推进，传统的图书馆管理模式已经难以满足现代图书馆运营的需求。纸质记录、人工管理的方式不仅效率低下，而且容易出现数据不一致、信息更新滞后等问题。特别是在高校、公共图书馆等场景中，图书借阅频率高、用户群体庞大，亟需一套高效、智能的图书管理系统来提升服务质量和管理效率。

### 1.2 教育背景
本项目作为数据库课程设计的重要组成部分，旨在通过实际的系统开发来深化对数据库理论知识的理解和应用。项目要求团队成员协作完成从需求分析、数据库设计到系统实现的全过程，体现了理论与实践相结合的教学理念。通过构建一个完整的图书馆管理系统，学生能够深入理解关系数据库的设计原理、SQL语言的实际应用以及数据库在现代信息系统中的核心作用。

### 1.3 技术背景
项目采用现代化的技术栈，包括：
- **后端**：Rust语言 + Actix-web框架 + Diesel ORM
- **数据库**：MySQL关系型数据库
- **前端**：React + TypeScript + Vite构建工具
- **认证**：JWT令牌认证机制
- **部署**：Docker容器化部署

这种技术选型既保证了系统的性能和安全性，又提供了良好的用户体验和可维护性。

### 1.4 业务背景
图书馆作为知识传播和学习支持的重要场所，其管理效率直接影响用户体验和服务质量。传统图书馆管理面临的主要挑战包括：
- 图书信息更新不及时，库存状态不准确
- 借阅流程繁琐，人工操作容易出错
- 缺乏有效的统计分析工具，难以进行数据驱动的决策
- 用户权限管理不够精细，安全性有待提升
- 缺乏现代化的用户界面，用户体验不佳

## 二、系统定位

### 2.1 系统目标
图书馆管理系统定位为一套面向现代图书馆的综合性管理解决方案，旨在通过信息化手段提升图书馆的管理效率、服务质量和用户体验。系统不仅要满足基本的图书借阅需求，更要提供智能化的管理工具和数据分析能力，支持图书馆的科学决策和精细化管理。

### 2.2 目标用户群体
系统主要服务于以下用户群体：

**图书馆管理员**
- 负责图书信息的维护和管理
- 需要全面的系统管理权限
- 关注库存状态、借阅统计等运营数据
- 需要高效的用户管理和权限控制工具

**普通读者用户**
- 图书借阅的主要参与者
- 需要便捷的图书查询和借阅功能
- 关注个人借阅历史和还书提醒
- 期望简单易用的操作界面

**系统维护人员**
- 负责系统的技术维护和优化
- 需要系统监控和故障诊断工具
- 关注系统性能和安全状况

### 2.3 系统特色定位
**教育性与实用性并重**
- 作为数据库课程的教学案例，体现数据库设计的完整流程
- 同时满足实际图书馆管理的业务需求
- 融合理论知识与实践应用

**现代化技术架构**
- 采用Rust语言保证系统性能和内存安全
- 使用React构建响应式用户界面
- 基于JWT的安全认证机制

**可扩展的权限模型**
- 基于RBAC（基于角色的访问控制）的权限设计
- 支持灵活的权限配置和扩展
- 细粒度的操作权限控制

## 三、系统功能规划

### 3.1 核心功能模块

#### 3.1.1 图书管理模块
**功能描述**：实现图书信息的全面管理，包括图书的添加、查询、修改和删除等操作。

**主要功能点**：
- 图书信息录入：支持ISBN、书名、作者、分类、出版社等信息的录入
- ISBN格式验证：自动验证ISBN号码的格式正确性
- 库存管理：实时跟踪图书的总数量和可借数量
- 图书搜索：支持按书名、作者、分类等多维度搜索
- 图书详情展示：显示完整的图书信息和库存状态
- 库存调整：管理员可手动调整图书库存数量

**技术实现**：
- 后端API：RESTful接口设计
- 数据验证：输入数据的格式和完整性验证
- 事务处理：保证库存数据的一致性
- 索引优化：针对搜索字段建立索引提升查询性能

#### 3.1.2 用户账户系统
**功能描述**：提供用户注册、登录、权限管理等账户相关功能。

**主要功能点**：
- 用户注册：支持用户名、密码、手机号等信息的注册
- 登录认证：基于JWT的令牌认证机制
- 权限管理：区分管理员和普通用户角色
- 用户信息维护：支持用户基本信息的修改
- 密码安全：密码加密存储和强度验证

**技术实现**：
- 密码加密：使用Argon2算法进行密码哈希
- JWT认证：无状态的认证机制
- 角色权限：基于角色的访问控制
- 会话管理：支持登录状态的维护和管理

#### 3.1.3 借阅管理模块
**功能描述**：实现图书借阅的核心业务流程，包括借书、还书、续借等功能。

**主要功能点**：
- 图书借阅：检查库存并创建借阅记录
- 借阅期限管理：默认7天的借阅期限
- 图书归还：更新库存和借阅状态
- 逾期处理：自动计算逾期天数
- 续借功能：支持一次续借，续借期限7天
- 借阅历史：记录用户的借阅历史

**技术实现**：
- 事务处理：保证借阅操作的原子性
- 库存检查：实时的库存状态验证
- 日期计算：准确的借阅期限和逾期计算
- 状态管理：借阅记录的完整状态跟踪

#### 3.1.4 统计分析模块
**功能描述**：提供图书馆运营的统计分析功能，支持管理决策。

**主要功能点**：
- 库存统计：显示总图书数量和分类统计
- 借阅排行榜：按借阅次数排序的热门图书
- 时间段分析：支持按时间范围筛选统计
- 数据可视化：直观的图表展示

**技术实现**：
- 聚合查询：使用SQL的聚合函数进行统计
- 索引优化：针对统计查询优化索引设计
- 缓存机制：提升统计数据的查询性能
- 数据导出：支持统计数据的导出功能

### 3.2 增强功能模块

#### 3.2.1 权限控制系统
**功能描述**：基于RBAC模型的细粒度权限控制系统。

**主要功能点**：
- 角色管理：定义管理员和普通用户角色
- 权限配置：为不同角色分配相应的操作权限
- 动态权限：支持运行时权限验证
- 审计日志：记录重要的操作日志

| 查看图书详情 | ✅ | ✅ | ✅ |
| 添加图书 | ✅ | ❌ | ❌ |
| 借阅图书 | ✅ | ✅ | ❌ |
| 归还图书 | ✅ | ✅（本人） | ❌ |
| 查看借阅历史 | ✅ | ✅（本人） | ❌ |
| 续借图书 | ✅ | ✅（本人） | ❌ |
| 查看所有用户 | ✅ | ❌ | ❌ |
| 查看所有借阅记录 | ✅ | ❌ | ❌ |
| 库存统计 | ✅ | ✅ | ✅ |
| 借阅排行榜 | ✅ | ✅ | ✅ |

#### 3.2.2 系统管理功能
**功能描述**：为系统管理员提供的高级管理功能。

**主要功能点**：
- 用户管理：查看和管理所有用户信息
- 借阅记录管理：查看所有借阅记录
- 系统配置：系统参数的配置和管理
- 数据备份：系统数据的备份和恢复
- 性能监控：系统运行状态的监控

#### 3.2.3 用户体验优化
**功能描述**：提升用户使用体验的各项功能。

**主要功能点**：
- 响应式设计：适配不同设备的屏幕尺寸
- 加载优化：提升页面加载速度
- 错误处理：友好的错误提示和处理
- 操作反馈：清晰的操作结果反馈
- 界面美化：现代化的用户界面设计

### 3.3 技术架构设计

#### 3.3.1 系统架构
**分层架构设计**：
- **表现层**：React前端应用，负责用户界面展示
- **业务逻辑层**：Rust后端服务，处理业务逻辑
- **数据访问层**：Diesel ORM，负责数据库操作
- **数据存储层**：MySQL数据库，存储系统数据

#### 3.3.2 数据库设计
**核心数据表**：
- **用户表（users）**：存储用户基本信息和权限
- **图书表（books）**：存储图书详细信息和库存
- **借阅记录表（borrow_records）**：存储借阅历史记录

**数据库优化**：
- 索引设计：针对查询频繁的字段建立索引
- 外键约束：保证数据的参照完整性
- 事务处理：确保数据操作的一致性
- 触发器：自动维护数据的更新时间

#### 3.3.3 安全设计
**安全措施**：
- 密码加密：使用强加密算法存储密码
- JWT认证：无状态的认证机制
- 输入验证：防止SQL注入和XSS攻击
- 权限控制：细粒度的操作权限验证
- HTTPS支持：数据传输加密

### 3.4 性能规划

#### 3.4.1 性能目标
- **响应时间**：API接口响应时间小于200ms
- **并发处理**：支持100个并发用户
- **数据容量**：支持10万条图书记录
- **系统可用性**：99.9%的系统可用性

#### 3.4.2 性能优化策略
- **数据库优化**：合理的索引设计和查询优化
- **缓存机制**：对频繁访问的数据进行缓存
- **前端优化**：代码分割和懒加载
- **负载均衡**：支持多实例部署

### 3.5 扩展性规划

#### 3.5.1 功能扩展
- **预约功能**：支持图书预约和到书提醒
- **评价系统**：用户可以对图书进行评价和评论
- **推荐系统**：基于用户行为的图书推荐
- **移动端**：开发移动应用支持

- **云原生**：支持容器化和云部署
